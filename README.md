# 把喜欢，写进每一天

一个温馨、简单的个人生日网站。原生 HTML / CSS / JavaScript，无需安装依赖。

## 开始使用
1. 使用较新的 Edge / Chrome 打开 `index.html`。
2. 点击「整理礼物」，填写昵称、生日、祝福、生日信和落款。
3. 在「我们的回忆」选择地点，再点「为这里添加故事」；也可以直接点「收藏一段回忆」，选择所属地点后添加多张照片。
4. 一个地点可以有多段故事。故事卡片展示自选封面、标题、简介和照片数量，点击打开照片详情；「返回地点故事列表」回到同一个地点。每张照片可以单独填写说明。
5. 在「冬日旅程」拖动西安的雪花到目的地，或点击/键盘选择城市。每条火车路线**到站并保存成功后**，对应城市旁单独出现旅行青蛙；点击只查看该地点的故事。西安直接点击爱心查看西安故事。广元→广元、重庆→重庆、济南→济南。沈阳飞机路线仍打开蛋糕台。
6. 完成蛋糕台的四个实际操作后，会出现烟花和许愿环节：选择「抹奶油」后在蛋糕上拖动；选择「裱花」后点击三次；选择「许愿」输入愿望，愿望会以发光文字浮现在蛋糕后方的空白背景；选择「插蜡烛」后点击三处插入蜡烛。完成过程中可以看到立体蛋糕逐步长出奶油、花朵和蜡烛。
7. 在「整理礼物」中导出分享页面，把生成的单个 HTML 文件私下发给她；她下载后使用浏览器打开即可。聊天软件内置预览可能不支持 HTML，需要另存到设备。

照片与已完成路线保存在当前浏览器的 IndexedDB，不会上传网络，不会跨设备同步。刷新页面会恢复已解锁青蛙，不会重新生成重复标记。清理浏览器数据、使用隐私模式或更换文件路径/浏览器可能导致内容无法读取。请定期点击「备份内容」保存 JSON；「恢复备份」可在其他设备导入。分享页面的故事是导出时的只读快照，但接收人仍可拖动旅行路线，自己的解锁进度独立保存，不会改变制作者的礼物。

## 编辑地点、故事和照片

- **地点**：「管理地点」可新增/改名、选择火车/飞机/爱心、调整地图坐标。新地点自动出现在地图和故事所属地点选项中，不需修改业务代码。西安保留为爱心起点。
- **故事**：在地点列表中点击「编辑」，可以修改名称、描述、日期、所属地点；「上移 / 下移」调整同一地点内的顺序。修改地点会移动故事，不复制照片。
- **照片**：再次多选上传会追加；每张照片有「设为封面、前移、后移、替换、删除」以及独立说明。封面选择不会打乱照片顺序。点击「收藏这段回忆」才提交；取消编辑不改变已保存内容。
- **旧数据**：版本 1 的无地点故事完整归入西安；版本 2 的地点故事保留归属和解锁记录。首次自动迁移时，原始数据另存于同一 IndexedDB 的 `before-v3-migration` 键。可以编辑故事重新分配地点。
- **编辑与游览**：制作者可提前整理尚未解锁地点的内容；地图上的青蛙以及分享页面的地点入口仍严格按到站状态开放。动画不等于访问权限，分享 HTML 本身包含全部照片。

本地文件存储在不同浏览器下行为有差异，长期使用建议通过固定的本地 HTTP 地址访问。Windows 无需安装 Node，运行 `powershell -ExecutionPolicy Bypass -File .\server.ps1`，访问 `http://127.0.0.1:4173`；如果已经安装 Node，也可以运行 `node server.cjs`。本地服务仅绑定本机。浏览器不支持存储时页面会提示，保存失败不会伪报成功。

## 项目文件
- `index.html`：页面和弹窗。
- `styles.css`：响应式设计与减少动画支持。
- `app.js`：本地保存、照片压缩、故事编辑、备份恢复和分享导出。
- `model.js`：独立的地点、故事、照片记录，归属校验、排序与旧数据迁移。
- `gift-sources.js`：分享页面所需的内嵌源码，已生成，可直接使用。
- `build.ps1`：修改 HTML/CSS/JS 后运行 `powershell -ExecutionPolicy Bypass -File .\build.ps1`，更新含数据模型的分享资源。
- `docs/PRD.md`：需求、范围、验收与设计方案。
- `docs/RESEARCH.md`：GitHub 项目、skill 来源与学习记录。

## 发布到 GitHub Pages（无需购买服务器）

本项目是纯静态 HTML/CSS/JavaScript，可以使用 GitHub Pages 发布。发布后得到一个 `https://用户名.github.io/仓库名/` 地址，局域网内的手机和电脑只要能访问互联网就可以打开；不需要在个人电脑上持续运行 PowerShell 服务。

1. 在 GitHub 新建一个仓库，把整个项目上传到仓库的 `main` 分支。请同时上传 `太聪明-陈绮贞.mp3`，歌曲文件名不要修改。
2. 确认仓库的 **Settings → Actions → General → Workflow permissions** 允许 Actions 写入仓库或 Pages。
3. 打开 **Settings → Pages**，在 **Build and deployment** 中选择 **GitHub Actions**。
4. 推送代码后，进入 **Actions** 查看 `Deploy birthday site to GitHub Pages`。显示成功后，在 **Settings → Pages** 查看访问地址。

仓库已经包含 `.github/workflows/deploy-pages.yml`，每次推送到 `main` 都会自动重新发布。首次打开时请点击“许一个生日愿望”，浏览器会在用户操作后播放歌曲；照片和编辑内容保存在当前设备的浏览器中，不会自动同步到 GitHub。

如果目标是“完全没有互联网、只在家中局域网访问”，GitHub Pages 无法提供这个能力，仍需要一台局域网设备运行静态文件服务。此时可在项目目录执行 `powershell -ExecutionPolicy Bypass -File .\server.ps1 -Port 4173`，并用运行电脑的局域网 IP 加端口访问，例如 `http://192.168.1.20:4173`。

不含账号系统或云端权限。页面未发布到公网；导出的 HTML 包含全部照片和文字，应只发给信任的人。所有插画独立编写，无外部图片、字体、音乐或追踪服务。
